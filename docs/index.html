Why this plugin

Claude Code keeps one login per config directory. Paseo can run each as its own provider, but then every model shows up once per account and a chat is stuck on the account it started on. This plugin puts all your logins behind the one Claude provider.

One provider in the pickers

Every model shows once. Your accounts live in the config but stay out of the pickers.

Switch from the header

A button in every workspace with a Claude chat shows the account in use and opens a native Paseo menu.

Chats keep their history

Open chats reload on the new login and resume the same conversation. Busy chats move once their turn ends.

Usage at a glance

Session (5h) and weekly usage per account, in the menu and in Paseo's own usage bar.

Sign in from anywhere

Finish the sign-in in the browser, or open the link on any device, your phone included, and paste the code.

Managed in Settings

Add accounts, sign in again when a login expires, or remove an account. The header menu only switches.

Install

One command. Paseo asks you to trust the plugin, clones it, runs npm ci and loads it.

paseo plugin install github:MaxGierlachowski/paseo-multi-account

On macOS the CLI ships inside the app: /Applications/Paseo.app/Contents/Resources/bin/paseo. If nothing shows up, check "pluginsEnabled": true in ~/.paseo/config.json and restart Paseo.

You need

  • Paseo 0.13.0 or newer, with plugins enabled
  • Claude Code (claude) on your PATH; signing in runs claude auth login
  • npm on your PATH, used once during install

Getting started

Two minutes from install to your first switch.

  1. Open Settings → Plugins → Claude accountsEverything that changes accounts lives here.
  2. Add an accountEnter a name such as Work and press Add. The plugin creates a provider claude-work with its own ~/.claude-work folder and starts the sign-in.
  3. Sign inFinish it in the browser that opens, or open the link on any device and paste the code into the Code field.
  4. Repeat for every login you haveWith two or more accounts, the account button appears in the workspace header.
  5. Chat on the built-in Claude provider as usualThe plugin decides which login each message goes out on. Switch from the header whenever you like.

How switching works

Switching is global: new chats, reopened chats and every open Claude chat move to the chosen account.

01

You pick an account

In the header menu. The plugin stores it as the active account.

02

Open chats reload

Idle chats right away; chats mid-turn or waiting on a permission once their turn ends.

03

History comes along

The chat's transcript is copied into the new account's folder. The original is never changed.

04

Claude resumes

Same conversation, new login. The next message runs on the account you picked.

Under the hood: each account is a disabled provider that extends claude and sets its own CLAUDE_CONFIG_DIR. Before Paseo opens a Claude session, the plugin points CLAUDE_CONFIG_DIR at the active account. Details in OVERVIEW.md.

Good to know

Start chats on Claude, not on an account provider. Account providers are disabled, and in Paseo 0.13 a disabled provider's chats don't open.

Removing is safe. Only the provider entry leaves the config. The login and its folder stay on disk and keep being searched, so old chats keep their history.

No toast after switching. Paseo's menus can't show one; the header button's label changing is the confirmation.

Update or uninstall

# pull the latest version
paseo plugin update claude-accounts-usage

# uninstall (accounts and logins stay)
paseo plugin remove claude-accounts-usage
